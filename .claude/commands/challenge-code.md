# /challenge-code — 代码质疑循环

对照设计文档，审查实现代码是否真正兑现了设计承诺。

## 使用方式

```
/challenge-code [docs/designs/xxx.md]
```

不指定文件时，对 `docs/designs/` 下最近修改的设计文档及其对应代码执行。

## 工作流程

执行以下循环（最多 2 轮）：

### 每轮操作

1. 读取目标设计文档
2. 根据设计文档中的组件名，找到对应的 Java 源文件（在 `src/` 下搜索）
3. 读取 `.claude/prompts/code-challenger.md` 获取代码质疑者的 system prompt
4. 使用 Agent tool 启动代码质疑者 subagent，prompt 格式：

```
[code-challenger.md 的完整内容]

---

## 设计文档

[设计文档全文]

---

## 实现代码

[所有相关源文件的内容，含文件路径]

---

请逐条对照设计文档审查代码实现。
```

5. 收到质疑者的反馈后：
   - 如果返回"实现与设计一致" → 循环结束，代码通过
   - 如果返回问题列表 → 修复代码中的问题
   - 进入下一轮

### 终止条件

- 质疑者声明"实现与设计一致" → 通过
- 达到 2 轮上限 → 将剩余问题列出，请用户决策
- 用户中断 → 停止

### 与 /challenge 的区别

| | /challenge（设计质疑） | /challenge-code（代码质疑） |
|---|---|---|
| 审查对象 | 自然语言设计文档 | Java 源代码 |
| 审查标准 | 逻辑是否闭合 | 实现是否匹配设计 |
| 质疑者 prompt | challenger.md | code-challenger.md |
| 最大轮次 | 3 | 2 |
| 触发时机 | 设计完成后、编码前 | 编码完成后、提交前 |
