# /challenge — 设计质疑循环

对当前设计文档启动对抗性审查循环，暴露逻辑漏洞。

## 使用方式

```
/challenge [docs/designs/xxx.md]
```

不指定文件时，对 `docs/designs/` 下最近修改的文件执行。

## 工作流程

执行以下循环（最多 3 轮）：

### 每轮操作

1. 读取目标设计文档的完整内容
2. 读取 `.claude/prompts/challenger.md` 获取质疑者的 system prompt
3. 使用 Agent tool 启动质疑者 subagent，prompt 格式：

```
[challenger.md 的完整内容]

---

## 待审查的设计文档

[设计文档全文]

---

## 上轮质疑记录（如有）

[上一轮的 Q&A]

---

请按照你的原则审查这份设计。如果上轮有未解决的问题，先检查是否真正被回答了。
输出格式：
- 如果有问题：列出最多 5 个问题，按严重程度排序，每个问题说明"为什么这是个问题"
- 如果没有问题：输出"设计逻辑闭合，无更多追问"
```

4. 收到质疑者的反馈后：
   - 如果返回"设计逻辑闭合" → 循环结束，告知用户设计通过
   - 如果返回问题列表 → 逐条分析并修改设计文档，将 Q&A 记录追加到文档的"质疑记录"章节
   - 进入下一轮

### 终止条件

- 质疑者声明"设计逻辑闭合" → 通过
- 达到 3 轮上限 → 将剩余未解决问题列出，请用户做人类决策
- 用户中断 → 停止

### 注意事项

- 每轮传给质疑者的是修改后的完整设计文档（不是 diff）
- 回应质疑时要修改设计文档本身，不是只在 Q&A 里写答案
- 质疑者是独立 subagent，不会被主 agent 的推理惯性影响
- 不要试图"说服"质疑者 — 如果它指出了真实问题，就修改设计
